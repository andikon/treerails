# Keep agent sessions in a persistent local host

Tree Rail will use a background session host and detachable UI clients so closing the UI does not end ticket work, accepting the additional lifecycle and reconnection work as a foundation for orchestration. The initial scope is the current user on the local machine, one controlling UI with explicit takeover, and survival of UI exit/disconnection while the host and operating-system user session remain alive; host-failure, sign-out and reboot recovery are separate concerns. The host owns live terminals, session attention and managed ticket-worktree ownership, while durable workflow references remain subject to [ADR 0001](0001-store-settings-and-remembered-state-in-one-config-file.md) and terminal state/scrollback remain bounded in host memory.

Start the host automatically when the ticket workflow needs it, preserving read-only listing behavior; no OS service or automatic login startup is required. Closing the UI detaches, while Stop session and Stop host remain explicit actions, and a host with no live sessions may exit. After host failure or reboot, preserve references and report Interrupted, reconcile remaining activity, and require explicit conversation resume rather than restarting agents or resending instructions automatically.
